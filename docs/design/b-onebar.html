B · ONE BET: CHROME

One Bar

Everything from Recut, plus one structural change: the pane header is deleted and the status line absorbs it. Session name, state dot, close button, profile, model, effort, permission mode, directory and sandbox backend all live on a single line at the bottom of each pane — next to the composer, which is where you are already looking when you care about any of them.

A pane costs 28px less. In a 2×2 that is 56px of transcript back; in a 4×4, 112px. Nothing is removed — the same nine facts are on screen, on one line instead of two.

What actually changed

  • Two bars become one. The pane header carried three things — a state dot, a name and a close button — and spent 28px doing it. All three fit in the gutter the status line already had spare.
  • Identity sits next to the input. "Which session am I about to send to, as which model, in which mode, in which directory" is now one unbroken line, read left to right, immediately above the thing you press ⏎ in.
  • The window header still names the focused pane, so the answer to "where am I" is never only at the bottom.
  • Everything else is Recut — same palette, same tool bars, same truncation, same gate.

What it costs

  • Titles move to the bottom. Scanning a 2×2 grid for "which pane is cerebro" means reading along the floor of each pane rather than the ceiling. Every other tabbed application on the machine puts it on top.
  • Long session names now compete with five status segments for one line. At a narrow pane width something has to truncate, and the honest answer is the name does.
  • Drag-to-rearrange loses its grip. The pane header was the handle you grabbed to move a pane in the grid; that needs somewhere new to live.
  • The win only shows up in a grid. With one pane open you have recovered 28px of a 700px column and changed where the title is for no reason.

Worth it if you genuinely run 2×2 and up. Close to neutral if you mostly run one pane.
