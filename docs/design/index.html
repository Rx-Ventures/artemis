Five ways to look at it

Five different layouts, not five palettes on the same frame. The brief was that Artemis currently reads as a Claude Code / T3 / Codex clone, so each of these changes the information architecture first and the colour second. New palette in every one, higher contrast throughout, OKLCH structure kept.

Nothing here is locked, and they are not meant to be ranked. The useful outcome is which bets you like — they can be mixed.

Every mockup renders the same real session, and it is one that actually happened — sandbox:check reporting an escape, the diagnosis, the fix, the re-run. The first pass at these was four turns and two tool calls, which proved nothing: nothing in it was hard to lay out.
a diff, +6 −3 a failing test run with two stacks a grep with 40 hits, truncated a command that failed, then a retry a todo list mutating across turns two delegated agents, still running 28 turns, scrolled mid-session context at 78% a gate on a command that runs unconfined
Judge them on that load. Which still reads at turn 28 with a diff, a stack trace and a truncated grep on screen at once — and which you could work in for six hours.

01

Instrument

Artemis as lab equipment. No cards, no shadows, no rounding — one plane divided by hairlines, meaning carried by position and a single acid signal. Monospace throughout. The status rail moves to the top, because "which account is this billing" is the first question, not the last.

02

Ledger

The session as an engineering logbook. Serif prose in a measured column, a margin carrying time and cost, tool calls set as citations rather than interruptions. No sidebar at all — sessions live behind ⌘K — and files open inline where they were mentioned instead of in a dock.

serifno sidebarno dockreads as a record
03

Yard

Stop pretending there is one conversation. The board is home — lanes by state (wants you / working / settled), conversations as cards, delegated agents nested visibly inside their parent. Opening one is a zoom, not a navigation: it peeks up from the bottom with the board still behind it.

biggest departuremulti-session firstboardshows delegation
04

Rail

Two things happen at once, so show two. Talk on the left, consequence on the right — the files, commands and pages it touched — with a shared timeline spine down the middle that both halves hang off. The dock stops being a drawer you open and becomes permanent and equal.

loudestmagentadock is half the screenshared spine
05

Quiet

Almost nothing until you ask. No sidebar, no tab strip, no status bar — the entire persistent UI is a 3px strip whose colour is state and whose width is context used. Everything else — sessions, files, terminals, settings — arrives through one overlay and leaves again. Type does the work boxes do elsewhere.

What I would ask yourself while clicking

  • How many sessions do you really run at once? If it is usually four, Yard is the only one designed for that and the rest are wrong. If it is usually one, Yard is overhead.
  • Do you read the transcript, or watch it? Ledger and Quiet assume reading; Instrument and Rail assume watching something happen.
  • Is the dock essential or occasional? Rail makes it permanent, Ledger deletes it, the rest keep it as tabs.
  • Monospace everywhere, or only for code? Instrument says everywhere; Ledger says almost nowhere.

Not decided here

These are single states of a single screen. Settings, profiles, first run, split panes, light mode and the permission modes all still need designing, and the winner will need a written token layer before any of the 52 components are converted — which is where this stops being mockups and starts being work.
